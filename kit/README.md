# Комплект 0.1-p3: от идеи до проверенного приращения

Агент применяет комплект к разрешённому проекту, сохраняет прежние правила и
задачи, ведёт файловую память и продолжает работу после ручного возвращения.
Пользователю достаточно описать потребность в чате и принимать принадлежащие ему
решения о продукте, архитектуре и расходах. Реализацию, обычные проверки и
исправления в разрешённых границах выполняет агент.

Поставка реализована. В реальной работе она ещё не испытана. Наличие инструкций и успешная диагностика не доказывают полезность
продукта, истинность отчётов или эффективность команды.

## Получить комплект через Git

Публичная поставка — [ai-dev-kit-ru](https://github.com/vasd85/ai-dev-kit-ru).
В репозитории находится только каталог `kit/`; документы подготовки в него
не входят. Из корня своего проекта клонируй поставку в свободную отдельную папку:

```sh
git clone https://github.com/vasd85/ai-dev-kit-ru.git .ai-dev-kit
```

После этого руководство находится в `.ai-dev-kit/kit/README.md`. Не клонируй
поставку поверх корня существующего Git-проекта. Если `.ai-dev-kit` уже занята,
сначала выясни её назначение; повторное клонирование и перезапись не нужны.

Передай агенту из корня своего проекта:

> Подключи комплект из `.ai-dev-kit/kit/README.md` к текущему проекту.
> Прочитай руководство и процедуру применения. Используй файлы прямо из клона,
> сохрани прежние правила и задачи. Настрой вход, память продукта и исключение
> папки поставки из Git продукта. Затем помоги мне проработать мою задачу.

Агент выполняет подключение по процедуре ниже. Само клонирование ещё не создаёт
память проекта и не подключает инструкции. В этом размещении рабочие файлы
находятся в `.ai-dev-kit/kit/`, а команды диагностики имеют вид:

```sh
GIT_OPTIONAL_LOCKS=0 python3 -B .ai-dev-kit/kit/tools/kit.py check --root "$PWD" --state docs/ai-work/state.json
```

История комплекта остаётся в его клоне. Правила конкретного продукта, решения и
задачи хранятся отдельно в самом проекте. Агент записывает точный коммит поставки
в профиле; обновление выполняется отдельно по `procedures/adapt.md`, §9.

## Начать применение

Прочитай [процедуру применения](procedures/adapt.md). Она определяет действующую
цепочку инструкций, размещение рабочей части, совместимость беклога, Git-процесс,
повтор, обновление и удаление. Первоначальный Git-осмотр в §1 сначала читает
настройки, атрибуты и сохранённые версии: status/рабочий diff могут запускать
преобразователи файлов и допустимы лишь после их разбора. В §6 есть готовый запрос первого применения и
явного начала чата, когда менять вход нельзя. Требуются путь к этой поставке и
разрешённый проект. Создание удалённого репозитория, публикация и выпуск требуют
своего разрешения; одно подключение их не разрешает.

При копировании рабочей части обычные места: `.ai-kit/` — правила,
`docs/ai-work/` — память продукта. Для Git-клона выше правила уже лежат в
`.ai-dev-kit/kit/`, второй копии не нужно. При
конфликте или подходящей существующей структуре агент выбирает другие места и
согласует указатели. [Фрагмент входа](entry/AGENTS.fragment.md) — образец короткого
указателя, его имя ничего автоматически не подключает. Переопределения и прежние
нормы сохраняются. Ссылка только в недействующем файле не считается подключением.

## Начать или продолжить работу в подключённом проекте

1. Явно прочитай действующий вход, этот README, заполненный профиль и единственный
   беклог, названные во входе. Прочитай точку продолжения и ограничения. Штатно это
   `docs/ai-work/project.md` и `continuation` в `docs/ai-work/state.json`, пути от
   Git-корня. Для чужого беклога профиль указывает его и границы проверки.
2. При смене сессии/остановке выполни [восстановление](procedures/recovery.md).
   Установи прежних исполнителей, неизвестные исходы и единственное право записи.
3. Для подготовки, назначения, исполнения, приёмки и интеграции используй
   [рабочий порядок](procedures/workflow.md) и [роли](procedures/roles.md).
   Поля и формальные ограничения — в [формате записей](formats.md).
4. Для новой идеи заполни [профиль](templates/project.md) и чистую
   [форму состояния](templates/state.json), без учебной работы и выдуманного
   разрешения. Дальние функции остаются идеями. План проверяется до исполнения.
   [Поручение](templates/work.md) помогает заполнить одну запись; [результат](templates/result.json)
   заполняется после реальной проверки. Для малой правки хватит профиля и одного
   состояния; функция и отдельные исполнители не обязательны.

## Исполняемая диагностика в продукте

Нужны локальные Python 3 и Git, установка библиотек не требуется. Проверенная
среда изготовления: macOS arm64, Python 3.14.6, Git 2.54.0. Другие версии/ОС
заранее не объявляются испытанными. Из канонического корня продукта:

```sh
GIT_OPTIONAL_LOCKS=0 python3 -B .ai-kit/tools/kit.py check --root "$PWD" --state docs/ai-work/state.json
```

При ином размещении подставь реальные пути. `--root` обязателен: обычный локальный
Git-репозиторий без symlink в корне/родителях; `--state` всегда относительно него.
Все три файла `tools/kit.py`, `tools/read_support.py`, `tools/records.py` нужны
рядом. Программа только читает, не запускает команды из записей, не меняет статусы,
не назначает работы, не делает коммиты, не останавливает процессы и не ходит в сеть.

Коды: 0 — формальных противоречий в заявленных действиях не найдено; 1 — ошибка
данных/связей/чтения; 2 — неподдерживаемая версия/конструкция или неверные CLI-
аргументы. Сообщается первая проблема с адресом. INFO о прогнозе/URL не меняет
успех. `inspect` заблокированной работы означает допустимое чтение, не разрешение
реализации. Чужой формат не поддерживается простым сопоставлением названий.

Проверяются текущие основания назначения/приёмки/передачи, точное содержание
поручений, принятые зависимости, мандат функции, этап подготовки/реализации,
единственный зарегистрированный писатель, прекращение попыток по сохранённым
фактам, общий пересмотр, входы по Git, остаток выбранных числовых ограничений.
История отделена от текущих оснований: новая законная редакция поручения не
стирает старое принятое подтверждение, если оно подходит нынешнему обязательству.
Папки входов включают новые неигнорируемые файлы; HEAD, индекс и рабочие входы
сравниваются с проверенным коммитом. Отдельный коммит отчёта не меняет входы.

Десятичные числа проверяются без двоичного округления. Закрытая функция освобождает
прямые и внутренние резервы; первичный расход сохраняется. Прогноз информационный;
настоящее ограничение действует отдельно. Программа не измеряет время, деньги или
квоту и не создаёт финансового барьера. Неизвестный обязательный остаток запрещает
соответствующий расход, а не независимое чтение.

Граница безопасности: локальная доверенная папка без конкурентной подмены путей.
Символические ссылки, include/includeIf конфигурации Git, gitfile/worktree,
внешние объекты, partial clone и неподдерживаемые расширения отклоняются. Внешние
обработчики Git не запускаются, чтение с `GIT_OPTIONAL_LOCKS=0` и очищенным
окружением. URL не загружаются; обязательный внешний источник остаётся непроверенным.
Подробности — в формате. Смысл критериев, полнота входов и фактическая остановка
остаются ответственностью агента.

## Версии и состав

`VERSION` — версия поставки `0.1-p3`. Поддерживаемые форматы записей: `0.1-p2`
и прежний ограниченный `0.1-p1`. Новое имя поставки не меняет JSON-формат и не
требует миграции корректных записей p2. Принятая диагностика пакета 2 сохранена.
Добавлены вход, адаптация и чистое начальное состояние. Полный список рабочей
части — 15 файлов в `procedures/adapt.md`, §3. Копировать один `kit.py` недостаточно.

Полная поставка также содержит пять файлов `tests/test_*.py` и учебные
`examples/walkthrough.md`, `examples/single-task.state.json`: всего 22 файла.
Они нужны изготовителю/проверяющему и присутствуют в полном Git-клоне. Рабочее
применение их не требует и не копирует учебную нормализацию в задачи продукта.
В Git-поставке точную редакцию всех файлов определяет коммит; при иной передаче
состав, размеры и SHA-256 сохраняются в отчёте изготовления вне продукта.

## Только для полной поставки: проверки изготовления

Эти команды требуют исходных `tests/` и `examples/`. Они не нужны подключённому
продукту и не заменяют его тесты. Из папки, содержащей полную `kit/`:

```sh
GIT_OPTIONAL_LOCKS=0 python3 -B -m unittest discover -s kit/tests -v
```

Разбор связанного примера — `examples/walkthrough.md` полной поставки. Генераторы
создают только новые собственные учебные репозитории и не заменяют существующие:

```sh
r1_parent="$(mktemp -d)"
python3 -B kit/tests/test_records.py --example "$r1_parent/repo"
recovery_parent="$(mktemp -d)"
python3 -B kit/tests/test_recovery.py --example "$recovery_parent/cases"
python3 -B kit/tests/test_recovery.py --feature-example "$recovery_parent/full-feature"
```

Старая p1-регрессия: `python3 -B kit/tests/test_kit.py --example /новый/каталог`
и `--stopped-example /другой/новый/каталог`. Первая даёт 0, остановленная ожидаемо
2 на `task/status`; это не обещание восстановления в p1. Поддержка p2 не получается
простой заменой номера версии. Фоновые службы, автоматическое пробуждение и сбор
необязательной статистики не входят в комплект.
