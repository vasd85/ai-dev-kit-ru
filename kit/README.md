# Комплект для разработки от идеи до проверенного результата

Точная версия — в [VERSION](VERSION), формат рабочих записей — в [договоре](formats.md#record-versions). Сведения о происхождении этой редакции и прежних проверках — в [справке](reference/decisions.md#evidence-and-history).

Получить опубликованную поставку можно командой `git clone https://github.com/vasd85/ai-dev-kit-ru.git .ai-dev-kit` из разрешённого корня продукта. Перед клонированием проверь [условия размещения](procedures/adapt.md#placement) и фактическую версию. Для локальной поставки укажи её путь и путь к продукту. Оба варианта начинаются с маршрута подключения.

<a id="entry-routes"></a>
## Маршруты по ближайшему действию

В подключённом проекте начни с действующего входа или переданного явного старта. Из него открой раздел «Подключение и единственные источники» заполненного профиля. Проверь корень, режим и единственный источник работ. Определи роль, ближайшее действие и наличие прежнего исполнения по [правилу старта](procedures/workflow.md#start-and-resume). Открывай указанные разделы вместе с обязательными переходами внутри них. Для каждого действия используй только нужные проектные данные и [применимые местные правила](procedures/project-rules.md#apply-project-rules).

<a id="nav-s01"></a>
### NAV-S01. Подключить комплект

До записи открой [разрешение и исходные источники](procedures/adapt.md#permission), [безопасный осмотр Git](procedures/adapt.md#git-inspection) и [действующий вход](procedures/adapt.md#effective-entry). Перед существенной подготовкой открой [план и делегирование](procedures/roles.md#delegation-and-plan). Перед записью установи [владельцев ресурсов](procedures/roles.md#shared-resources). Затем выбери [размещение](procedures/adapt.md#placement) и [профиль, режим и источник](procedures/adapt.md#project-profile). Открой применимые формы оттуда. После установки пройди [проверку подключения](procedures/adapt.md#install-check), включая путь к следующему допустимому действию.

<a id="nav-s02"></a>
### NAV-S02. Ответить на вопрос или составить план

Для вопроса о команде открой её источник из раздела «Среда и команды» профиля. Достаточно точной команды, рабочей папки и условий. Для вопроса о ходе работы открой точку продолжения, нужную карточку и факт проверки. Короткое уточнение требует освежить изменившееся. Для небольшой правки сначала открой [короткий путь](procedures/workflow.md#short-path), затем применимые входы исполнения.

До существенного плана открой [полномочия](procedures/roles.md#authority), [делегирование](procedures/roles.md#delegation-and-plan), [планирование итерации](procedures/workflow.md#plan-iteration) и местные нормы постановки. Установи результат, границы, стоимость и способ проверки. До назначения открой [подготовку поручения](procedures/workflow.md#assignment), [проверки переходов](procedures/workflow.md#diagnostic-transitions) и [прогресс и расходы](procedures/workflow.md#progress-and-cost).

<a id="nav-s03"></a>
### NAV-S03. Исполнить первое назначение

Открой [порядок исполнения](procedures/workflow.md#execute) и пройди его предпосылки до записи. Нужны точное поручение, текущая попытка, существенные входы и местные правила, принятые зависимости и общий контекст за пределами карточки. Для местной функции добавь принятое общее поручение. До записи результата открой [договор результата](formats.md#results-and-acceptance), до сообщения — [правило отчёта](procedures/workflow.md#reporting). При неизвестном прежнем исполнении используй NAV-S04.

<a id="nav-s04"></a>
### NAV-S04. Восстановить работу

Открой [восстановление](procedures/recovery.md#resume) и точку продолжения с нужными назначениями, ресурсами и незавершёнными действиями. Неизвестный внешний исход требует [разбора](procedures/recovery.md#uncertain-outcome), изменение решения или входов — [пересмотра](procedures/recovery.md#reassess). Для штатных записей сначала установи [версию](formats.md#record-versions). По результату выбери разрешённое продолжение либо чтение и разбор. Для нового назначения затем пройди NAV-S03.

<a id="nav-s05"></a>
### NAV-S05. Проверить, принять или передать результат

Открой [порядок ревью и приёмки](procedures/workflow.md#review-and-acceptance) и предъявленную редакцию. Для независимой критики установи охват, доступ и применимые местные правила. До приёмки и передачи дополнительно пройди переходы к полномочиям, договору результата, зависимостям и диагностике из процедуры. Для изменившихся входов используй [пересмотр](procedures/recovery.md#reassess). До сообщения открой [правило отчёта](procedures/workflow.md#reporting).

<a id="nav-s06"></a>
### NAV-S06. Добавить правило продукта

До подготовки открой [сопровождение норм](procedures/project-rules.md#maintain-rules), действующие предметные источники и [полномочия](procedures/roles.md#authority). Для существенного плана используй NAV-S02. До записи проверь затронутые поручения и ресурсы как в NAV-S07. После правки проследи [маршруты потребителей](procedures/project-rules.md#apply-project-rules) до единственного определения и [проверку по критериям](procedures/workflow.md#review-and-acceptance).

<a id="nav-s07"></a>
### NAV-S07. Изменить, перенести или удалить правило продукта

Открой местную норму и [сопровождение норм](procedures/project-rules.md#maintain-rules). До записи найди потребителей, редактора, область и активные поручения. Если меняется решение, поручение, проверенный вход или общий ресурс, открой соответствующий переход в процедуре, включая [пересмотр](procedures/recovery.md#reassess). Перед зависимым действием убедись, что актуальная редакция доведена до исполнителя и её основания проверены.

<a id="nav-s08"></a>
### NAV-S08. Узнать основание решения

Открой актуальную норму и редакцию. Для причины открой связанное решение продукта либо [справку комплекта](reference/decisions.md#evidence-and-history). При существенном сомнении открой первичное свидетельство. Используй ссылку из определения, если указан отдельный адрес причины. Если основание недоступно, укажи границу известного. Чтобы после ответа выполнить действие, вернись к его маршруту и действующему поручению.

<a id="update-route"></a>
### Обновить поставку или вернуться к прежней

Для пользователя с клоном `.ai-dev-kit/` на ветке `main` без местных изменений: заверши использующие комплект исполнения и сохрани точку продолжения. Из корня продукта сначала получи прежний коммит и сохрани выведенную строку:

```sh
git -C .ai-dev-kit rev-parse HEAD
```

Затем получи обновление:

```sh
git -C .ai-dev-kit pull --ff-only origin main
```

Если Git сообщил об ошибке или конфликте, передай сообщение агенту для разбора. После успешного обновления открой новый чат в проекте и передай:

> Обнови подключение кита в этом проекте по `.ai-dev-kit/kit/procedures/adapt.md#update-and-rollback`, включая раздел «Если пользователь уже выполнил git pull». Прежний коммит: `<сохранённая строка>`. Разрешаю необходимые правки входных инструкций и документов проекта. Сохрани местные правила, задачи и историю; сам клон не редактируй. Проверь результат, сообщи, что изменено и что можно продолжать. Продуктовую разработку этим запросом не начинай.

Если коммит не сохранён, так и укажи. Для другого пути клона замени путь в командах и запросе. При копированной установке или подготовке до `pull` начни сразу с [процедуры обновления](procedures/adapt.md#update-and-rollback). Для перехода к этой версии там есть [проверки p5](procedures/adapt.md#update-to-p5).

Агенту: установи прежнюю и полученную версии и вход; прочитай [порядок обновления и возврата](procedures/adapt.md#update-and-rollback). Из p4 начни с §1–2, §5 и §9 прежнего `procedures/adapt.md`, при чужом источнике добавь §7. После `pull` прежний текст получи из установленного исходного коммита по процедуре.
