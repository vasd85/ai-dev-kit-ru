# Подготовка поручения 0.1-p2

Действующий текст хранится один раз: в `work.assignment` состояния либо во внешнем JSON по `assignment.path`. Этот лист — инструкция, не вторая заполненная копия. Чистая `state.json` не содержит назначений; учебное поручение отдельно в `examples/single-task.state.json` полной поставки. Для чужого беклога сначала выбранный режим из `procedures/adapt.md`, а не автоматическое создание штатной очереди. Пользователь работает в чате; запись готовит агент.

1. Связать цель с потребностью и границами. Для раннего вопроса выбрать `kind:question`, `stage:prepare` и критерий ответа. Будущую идею оставить `candidate` с `idea`, без выдуманного назначения.
2. Определить существенные входы `inputs`: профиль, нормативное разрешение `authority.source`, выбранные решения, код, тесты и настройки. Файлы/папки внутри корня; весь корень автоматически не включать. `write_scope` обозначает разрешённый общий ресурс внутри входов; у анализа он пустой. Внутри папки учитываются новые неигнорируемые исходники. Не заявлять Git-проверку секретов/неизвестной внешней среды.
3. Сформулировать `criteria` с ID и наблюдаемым ожиданием, затем короткий `plan`. `acceptor` — логическая роль редактора этой области. Справочный прогноз хранить у координатора; исполнителю обычно достаточно цели, границ, проверок и настоящих ограничений.
4. Указать зависимости `work`, `criterion`, точную `acceptance`. Для будущей незапущенной работы приёмка может быть `null`. Перед текущим действием выбрать принятую редакцию и `bases`: результат, редакцию и проверку, явно покрывающие нужное обязательство на нынешних входах. Замена сохраняет прежнюю ссылку, причину и роль.
5. Назначить новую попытку с новым ID, редакцией поручения, исполнителем, фазой и эффектами. Сначала выяснить судьбу прежнего исполнения. Одна непрекращённая пишущая попытка удерживает общий отрезок, даже при паузе/отмене. Два активных писателя запрещены. Git и изменяющие папку тесты входят в это же право.
6. Для функции добавить `mandate` с логической ролью, этапами, общими интерфейсами и условием закрытия; сослаться на единственное `local_state`. Местная область фиксирует редакцию и коммит принятого общего поручения. Общее состояние назначает область-владельца, конкретную местную попытку выбирает местный координатор.
7. Сохранить текущее `actions`, достаточное `continuation` и выполнить `check`. Для `ready` требуется `assign`, для `in_progress` — `execute`. После сохранения входов в Git и фактической проверки представить результат в текущей попытке и `review`. Принять может та же сессия в роли принимающего, но это отдельное содержательное действие; независимым такой разбор не является.

Номер редакции не заменяет содержание: изменение цели, границ, входов или критерия требует пересмотра. Старая приёмка остаётся историей. Блокировка передаёт причину и шаг устранения через `inspect`, а не выдуманное разрешение писать. Полные поля — в [договоре записей](../formats.md).
