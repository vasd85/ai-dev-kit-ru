# Три карточки учебного проекта

Все пути отсчитываются от корня учебного проекта. Заполненный профиль
`ops/project.md` выбирает каталог `planning/new work`. Корневой вход
`AGENTS.md` называет этот профиль и [маршрут карточек](../README.md#task-cards).
Правила полей и адресов задаёт [договор](../formats.md#task-format).

## Маленькая задача, которой нужна проверка

`planning/new work/open/T-008-empty-search/task.json` открывается по `P/T-008`.
Форма содержит конкретное условие и остаток. Разрешение в примере касается
проверки, поэтому список путей записи пуст.

```json
{
  "format_version": "0.3.0",
  "id": "T-008",
  "title": "Сообщение при пустом поиске",
  "goal": "Объяснить отсутствие результатов",
  "assignment": {
    "revision": 1,
    "description": "При запросе без совпадений поиск сохраняет текст и показывает подсказку.",
    "boundaries": "Проверить только поведение пустого поиска в учебном проекте",
    "write_scope": [],
    "authority": {"by": "Владелец проекта", "source": "ops/project.md"},
    "acceptor": "Координатор",
    "criteria": [{"id": "C-1", "expectation": "При отсутствии результатов виден текст «Ничего не найдено»."}]
  },
  "waiting": {
    "remaining": "Проверить текст на экране при запросе без совпадений.",
    "reason": "Результат ручной проверки экрана ещё не записан.",
    "next_step": "Открыть поиск, ввести «zz-no-results» и сверить видимый текст."
  }
}
```

При длинном описании замени значение `description` на
`{"path":"description.md"}` и положи полный текст рядом с карточкой.
Карточка по-прежнему хранит критерий. При записи идеи достаточно четырёх
полей: версии, номера, названия и цели.

## Та же работа как потребитель принятого результата

Когда сообщение зависит от пустого ответа поиска, добавь в карточку
потребителя одну связь.

```json
{
  "dependencies": [
    {"task": "F-search/T-008", "criterion": "C-1", "acceptance": "A-search"}
  ]
}
```

Работа `F-search/T-008` имеет тот же местный номер и отдельный полный номер.
В карточке поставщика условие `C-1` означает «Запрос без совпадений возвращает
пустой список», а последнее решение выглядит так:

```json
{
  "observations": [
    {
      "id": "O-1",
      "by": "Автор учебных данных",
      "date": "2026-11-21",
      "revision": 1,
      "criteria": ["C-1"],
      "fact": "Учебное наблюдение о пустом списке в ответе",
      "source": "Подготовленные данные примера"
    }
  ],
  "decisions": [
    {
      "id": "A-search",
      "outcome": "accepted",
      "role": "Координатор",
      "by": "Автор учебных данных",
      "date": "2026-11-21",
      "revision": 1,
      "reason": "Наблюдение покрывает критерий этой редакции",
      "observations": ["O-1"]
    }
  ]
}
```

Поставщик расположен в `planning/new work/features/F-search/done/T-008-empty-result`.
Читатель проходит по зависимости в архив этой области. При необходимости
вложить карточку в дерево используй отдельное поле `parent` у ребёнка.
Общая карточка хранит собственный критерий о тексте, местная — свой
критерий об ответе. Сведения о выполнении берутся из соответствующей карточки.

Перед передачей такой приёмки укажи в решении `basis` со снимком карточки
и входов, на которых установлен пустой ответ, и применённый `mandate`
из местного `scope.md`. Для назначения зависимой работы добавь в её связь
адрес сохранённой карточки поставщика с решением
`A-search` и наблюдениями. [Договор действий](../formats.md#card-actions).

## Старая работа с неустановленной приёмкой

Исторический список содержит отметку Done. Карточка открыта, потому что
пока сохранился только этот факт. Восстановленная отметка указывает источник
и не подменяет решение принимающего.

```json
{
  "format_version": "0.3.0",
  "id": "T-010",
  "title": "Проверка старого экспорта",
  "goal": "Установить, сохранился ли файл открытия экспорта",
  "origin": {"status": "Done", "source": "Учебный старый список, строка 4"},
  "waiting": {
    "remaining": "Проверить открытие файла экспорта.",
    "reason": "Сохранилась только отметка Done.",
    "next_step": "Найти проверяемый файл и установить критерий проверки."
  }
}
```

Если позже найдено достаточное свидетельство, принимающий сверяет его,
устанавливает редакцию поручения и датирует новое решение моментом приёмки.
Старую дату можно восстановить по исторической карточке этой задачи
с решением и его наблюдениями.
Если материал сохранился в Git, его источник можно указать коммитом и
путём того снимка. Тогда перемещение живой карточки не меняет адрес свидетельства.

## Как воспроизвести обе редакции

Из корня полной локальной поставки, где видны `kit/` и `docs/`, выполни
`python3 -B kit/tests/test_task_cards.py --demo`. Сценарий создаёт свою
временную учебную копию, два локальных коммита и запускает команды через
установленный `.ai-kit/tools/kit.py` из корня копии. Вывод показывает поиск
`P/T-008`, ответ о её остатке, открытие архивного `F-search/T-008`,
две версии отчёта задачи `P/T-009` и три независимых исторических адреса.
Отдельно показаны отказы для неверного ключа, пути за разрешённой границей
и символической ссылки вместо исторического файла.

## Перенос исследовательского комплекта

Исследование `P/T-008` хранит `report.md` и `review.md` внутри
`docs/tasks/open/T-008-search-study/`. Сохрани в Git итоговый отчёт и
заключение по этим путям. После приёмки владелец требований записывает
действующее правило в `docs/product/search.md`. Задача `F-search/T-004`
указывает этот файл как существенный вход и выбирает в зависимости критерий
исследования и приёмку с её сохранённым адресом.

Редактор готовит [осмотр и перенос](../procedures/workflow.md#card-move).
Если отчёт ссылается на заключение в той же папке, запись осмотра выглядит так.

```json
{
  "document": {"task": "P/T-008", "path": "report.md"},
  "target": {"task": "P/T-008", "path": "review.md"},
  "relative": "review.md",
  "owner": "Автор исследования"
}
```

После переноса зависимая карточка открывает `P/T-008` по прежнему номеру.
Живой отчёт доступен через `read --task P/T-008 --path report.md` с профилем.
Исторический отчёт читается через `read --commit КОММИТ --path docs/tasks/open/T-008-search-study/report.md`.
